# 现场模拟首轮淘汰评测

## 方法

同一副牌、同一主角座位，五个方案各打到底。主角使用 `Agent.act`，传入线上相同的出牌历史似然，其余两家用 plain DouZero。评测没有叫分或加倍证据。主角座位逐副轮换，每副按种子打乱方案运行顺序。同一历史下，未进入淘汰调度的决策（初始候选少于四手或未模拟）共用一次实际运行结果和耗时。同一局面里对手牌的抽样继续用线上种子。

S0 首轮下限 12 局，按均分淘汰一半。S1 首轮下限分别为 20、30 局，后续淘汰轮仍为 12 局。S2 首轮保留与头名均分相差不超过 0.25、0.50 的候选，原始 DouZero 首选与不拆牌保护候选同样保留，之后恢复原淘汰规则。五种方案共用 2.5 秒模拟上限、3.5 秒总出牌时限和每候选 300 局上限。

按 S0 实际进入模拟且初始候选 ≥3 的整局纳入配对，每个种子和座位只计一副。三候选会进入模拟但只打一轮，表中另列初始候选 ≥4 的次数。每副的得分为赢 `+2^炸弹数`、输 `-2^炸弹数`，和现场模拟的计分单位一致。配对差先逐副减去对应 S0，标准误为差值的样本标准差除以配对数的平方根。每手耗时含主角整次决策，触发手耗时只统计进入模拟且候选 ≥3 的决策。

使用 `a9b9931f` 的 DouZero 实现、`douzero_ADP` 权重和 Apple M3 Max。计时使用真实钟，进程调度和线上暂停可能影响实际局数。不同方案选出不同的牌后，后续触发次数和每局手数可以随牌路改变。

```sh
# 在 tools/douzero 下，使用安装了 DouZero 的 Python
DOUZERO_WEIGHTS=/path/to/douzero_ADP python eval_halving.py --deals 420 --workers 4 --seed 20261120 --out /tmp/halving.jsonl
```

## 排期与选择

表中局数是各轮新增的每手局数。硬时限可使首轮达不到下限。8 手局面，S0 / S1-20 / S1-30 的决赛新增中位数分别为 67 / 37 / 0 局。三者首轮均留四手。S1-30 推迟首轮淘汰后，第二轮也经常凑不齐 12 局。

S2 能留住比分接近的牌。初始有五至八手、首轮已只剩一至两手时，现有调度器会在下一轮后提前结束。这解释了部分延迟下降。此次采用现有调度，提前结束时可能留有剩余预算。
